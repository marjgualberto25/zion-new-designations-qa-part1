# Business Rules

[← Back to README](../README.md)

| Rule ID | Area | Rule | Value / Note |
|---|---|---|---|
| BR-01 | Designation | MP and EP are created in System A under the Zion channel | Code MP = Managing Partner; Code EP = Executive Partner |
| BR-02 | Designation | System B designation config holds MP and EP with the same code and description as System A | Added by the System B team |
| BR-03 | Designation | Designation codes are unique within a channel | Duplicate code is rejected |
| BR-04 | Product setup | MP and EP are added to the product setup of each product line under Zion | 4 lines × 2 designations = 8 config lines |
| BR-05 | Product setup | Effective From Date = 2026-12-10; Effective To Date = blank (open-ended) | Applies to MP and EP only |
| BR-06 | Product setup | Effective dates are checked against the policy issue date | Issue date < 2026-12-10 with an MP/EP agent is rejected |
| BR-07 | Product setup | MP and EP may sell only the four Zion product lines | Any other product is not available to them |
| BR-08 | Hierarchy | System A stores hierarchy as pairwise records: Level 1 = subordinate, Level 2 = superior | Displays as Level 1 → Level 2 |
| BR-09 | Hierarchy | New records: 103 SFA → MP; 104 MP → EP | Existing: 101 JFA → FA; 102 FA → SFA (unchanged) |
| BR-10 | Hierarchy | EP is the top of the hierarchy and self-reporting: record 105 holds EP as Level 1 only | Level 2 is blank |
| BR-11 | Agent profile | Agent code is generated by System A when the profile is saved; it is unique and read-only | — |
| BR-12 | Agent profile | An agent's upline must hold the next higher designation (no skipping, no downward reporting) | e.g. JFA under MP is rejected |
| BR-13 | Agent profile | 'Self-reporting?' tickbox: required for EP; not allowed for other designations | EP is saved with no upline |
| BR-14 | Agent profile | A profile with an expired licence can be saved; licence status shows Expired | — |
| BR-15 | Integration | Agent profiles created in System A are passed to System B via API | Code, name, designation, channel, licence status |
| BR-16 | Proposal | Entering an agent code in a System B proposal displays the agent's name | Unknown code shows an error |
| BR-17 | Proposal | A proposal with an expired-licence agent cannot be submitted | Message: 'Agent License is expired' |

## Assumptions

- **A-01:** Reference codes 103, 104 and 105 are illustrative; System A assigns the actual values.
- **A-02:** UI messages are illustrative except 'Agent License is expired', which is confirmed by the business.
- **A-03:** Test agents are created top-down (EP first) so each upline exists before its subordinates.
- **A-04:** Issue-date tests need the SIT business date set to the stated date, or an issue date that can be entered for testing.
- **A-05:** 'GoldenYears PHP' is a fictional product that exists in the insurer's catalogue but is not set up for Zion; it is used only for negative testing.
